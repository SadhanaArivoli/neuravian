## What NeuroForge is

NeuroForge is a local-first neuroimaging research platform. It gives existing tools — FSL,
FreeSurfer, fMRIPrep, MRIQC, Nilearn, and others — a shared workspace with reproducibility,
traceability, and publication workflow built in from the start. It does not reimplement any
validated neuroimaging algorithm. All data stays on the researcher's machine.

The core design premises are:

- **Manifest-driven.** Every pipeline is declared in a YAML file. No pipeline logic is
  hardcoded in application code. Adding a tool means writing a manifest.
- **Artifact-typed.** Every run produces typed outputs. The system knows what each pipeline
  can consume and automatically surfaces compatible next steps.
- **Provenance-first.** Every run records the tool name and version, full command, all
  parameters, container image digest, input and output artifact paths, start time, end
  time, and exit code. This record is immutable.
- **Local-first.** No cloud account, no data upload, no telemetry by default.

## Major platform capabilities

**Dataset and project management**
- Import BIDS datasets from local directories; datasets are mounted read-only
- Project workspace with lab notebook and dataset association
- BIDS validation integrated as a first-class pipeline

**Pipeline execution**
- 20 core pipelines across conversion, validation, QC, skull stripping, segmentation,
  preprocessing, functional connectivity, de-identification, and analysis
- Sequential execution queue with cancel, retry, re-run, and duplicate
- Native executor (Python subprocess) for Nilearn, nibabel, and NetworkX tools
- Docker executor (Docker SDK) for containerised tools (MRIQC, FastSurfer, and others)
- Stalled-run detection and automatic recovery on restart
- Per-pipeline parameter forms with typed defaults, validation, and help text
- Plain-English error translation for known failure patterns

**Artifact Explorer**
- Every run output is catalogued as a typed artifact
- Inline previews: NIfTI viewer (NiiVue), matrix heatmap, HTML report embed, CSV table
- "Run Next" — one-click launch of compatible downstream pipelines from any artifact
- Filter by type, pipeline, and display mode

**Analysis Graph**
- Directed graph of all runs and artifact dependencies for each dataset
- Click any node to navigate to the run detail page
- Filterable by pipeline and status

**Comparison Studio**
- Side-by-side run comparison with quantitative metrics
- Skull-strip comparisons: Dice coefficient, difference NIfTI overlay
- Connectivity matrix comparisons: Frobenius norm, correlation, difference heatmap
- Same-source vs. unverified comparison classification based on confirmed lineage

**Workflow Builder and Library**
- Build named multi-step workflows from any sequence of pipelines
- Seven built-in workflow templates (BIDS + QC, fMRI Preprocessing, Functional
  Connectivity, Skull Strip + Segment, Seed FC → Statistical Map, ALFF/fALFF,
  Regional Homogeneity)
- Save, load, export, and import workflows

## Reproducibility and reporting

**Provenance records.** Every run records: pipeline ID, display name, tool version,
Docker image and digest (where applicable), full command executed, all parameters
(including defaults), input artifact IDs and paths, output artifact IDs and paths,
start time, finish time, and exit code. Records are immutable once written.

**Methods Studio.** Generates a draft methods paragraph directly from provenance
records — not from a language model. The paragraph names tools, versions, atlases,
parameters, and confound strategies in the format a methods section expects.

**Citation Studio.** Assembles a reference list from pipeline registry metadata.

**Study Report Studio.** Compiles a full dataset report as structured HTML with
PDF export. Multiple reports can be compared structurally.

## Plugin SDK

NeuroForge includes a plugin system that lets external developers add pipelines
without modifying core source code. Drop a directory into `plugins/` and restart.

A plugin can contribute:
- One or more pipeline manifests (same YAML schema as core pipelines)
- New artifact type definitions
- Native executables added automatically to PATH

Plugins are validated against a JSON Schema at startup. Invalid plugins are
isolated and reported in the Plugins page (`/plugins`) without preventing NeuroForge
from starting.

A working reference plugin (`plugins/image-statistics/`) ships with the repository
and demonstrates all plugin features.

Full documentation: [`docs/plugin-development.md`](../plugin-development.md)
Tutorial: [`docs/plugin-tutorial.md`](../plugin-tutorial.md)

## Installation

**Requirements:** Docker Desktop 4+, Git, 8 GB RAM (16 GB recommended for FastSurfer).
macOS and Linux are supported. Windows via WSL2 is functional but not tested in CI.

```bash
git clone https://github.com/SadhanaArivoli/neuroforge.git
cd neuroforge
cp .env.example .env        # set HOST_DATASETS_DIR to your datasets folder
docker compose up --build
```

Open `http://localhost:3000` when the backend reports `Application startup complete`.

See [`docs/quickstart.md`](../quickstart.md) for a step-by-step walkthrough.

## Known limitations

**Apple Silicon (M1/M2/M3).** Pipelines using `linux/amd64` images run under Rosetta 2:
- `local-ok` pipelines and all native Python tools are unaffected
- SynthStrip is functional but slower (5–15 min per subject)
- FastSurfer is functional but significantly slower than native x86_64
- **fMRIPrep** is marked `local-unsafe` — ANTs non-linear registration under Rosetta 2
  produces unreliable outputs and excessive memory use. Use Import fMRIPrep Derivatives
  to bring in results computed on a Linux machine or HPC cluster.
- pydeface is marked `local-unsafe` / unverified on Apple Silicon

**Sequential execution.** One pipeline runs at a time. Parallel execution is not
implemented in this release.

**Remote execution.** The SSH executor module and Remote Hosts settings page exist
in the codebase but are not yet connected to the run creation flow.

**Single-user only.** No authentication, role-based access, or multi-user support.

**Workflow state is partially session-bound.** Named workflows persist in SQLite and
survive restarts. The active step pointer within a running workflow sequence is held
in frontend state and is lost on page close.

**No HIPAA compliance.** NeuroForge does not implement encryption at rest, formal audit
logging, or any certified security controls. It is not suitable for processing identifiable
patient data in a clinical or regulated context.

## Alpha warning

This is an alpha release. It may contain bugs, incomplete features, and breaking
changes between versions. APIs and data formats are not yet stable.

- Do not use NeuroForge in clinical or diagnostic workflows.
- Do not rely on it as the sole record of your analysis — maintain independent logs.
- Test against a copy of your data before running it on your primary dataset.
- Report issues at https://github.com/SadhanaArivoli/neuroforge/issues.

The provenance records, database schema, and artifact directory structure may change
between alpha versions. Migration scripts will be provided where feasible.

- **Bug reports:** [GitHub Issues](https://github.com/SadhanaArivoli/neuroforge/issues)

- **Security issues:** see [SECURITY.md](../../SECURITY.md) — do not open a public issue
  for a vulnerability.
- **General discussion:** GitHub Discussions (if enabled) or the issue tracker.
