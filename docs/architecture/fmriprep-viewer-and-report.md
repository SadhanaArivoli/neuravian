# fMRIPrep report and scientific viewer architecture

## Scope and scientific authority

Neuravian treats the official participant HTML generated by fMRIPrep as the primary quality-control record. The interactive Neuravian viewer is a complementary derivative-inspection surface. It does not replace the official SVG reportlets, alter fMRIPrep outputs, infer registration success, or resample files behind the user's back.

This integration is frontend and file-serving infrastructure. It does not change the fMRIPrep command, container, inputs, outputs, or scientific algorithms. Existing completed runs receive the new browser and viewer because the UI classifies the files already present in each run output directory.

## Run-scoped report trace

For Run #5, the backend resolves the run output root and exposes the participant report at:

`/api/runs/5/files/sub-01.html`

The HTML uses its original relative references, including paths such as:

`./sub-01/figures/sub-01_dseg.svg`

The browser resolves that URL to:

`/api/runs/5/files/sub-01/figures/sub-01_dseg.svg`

No HTML rewriting, asset copying, or host-path exposure is required. Both requests pass through the existing run-scoped file endpoint, which resolves the requested path and rejects traversal outside the run output root.

## Embedded-report root cause and security policy

The EC2 public gateway previously applied `X-Frame-Options: DENY` to every response. The official report worked as a standalone page but was blocked when loaded in Neuravian's iframe. The same blanket policy also blocked reportlet SVGs loaded by the report in nested object contexts.

The gateway now applies a narrow exception only to run-scoped `.html` and `.svg` responses:

- `X-Frame-Options: SAMEORIGIN`
- `Content-Security-Policy: frame-ancestors 'self'`

All other gateway responses retain `X-Frame-Options: DENY`. The application file endpoint mirrors the same-origin policy for report HTML and SVG. The report iframe is sandboxed with only scripts, same-origin access, and popups enabled. Authentication, TLS, path containment, and the ban on arbitrary filesystem browsing remain unchanged.

## Central derivative classification

`frontend/src/lib/fmriprepArtifacts.ts` is the single fMRIPrep classification layer. It parses BIDS entities from each run-relative filename and assigns:

- semantic role;
- modality;
- subject, session, task, run, space, descriptor, and label entities;
- visualization mode;
- preferred base type;
- overlay semantics;
- output-browser section.

The classifier distinguishes structural intensities, binary masks, discrete segmentations, continuous probability maps, functional references, 4D preprocessed BOLD, confounds, transforms, official reports, and reportlets. Raw host paths are never part of this model.

## Pairing and geometry safety

Automatic base/overlay pairing requires compatible BIDS subject/session entities and exact space equality. Functional masks additionally require compatible task/run entities. After pairing, the shared `NeuroImageViewer` performs its existing dimensions, voxel-size, and affine compatibility check. An incompatible overlay is withheld with an explanation; no implicit resampling occurs.

Scientific display profiles are centralized in `scientificDisplayProfiles.ts`:

- structural T1w and BOLD reference: grayscale, smooth interpolation, robust finite range;
- binary mask: discrete binary display, nearest-neighbor interpolation;
- dseg: categorical label colors, nearest-neighbor interpolation;
- probability map: continuous viridis display with a threshold control;
- 4D preprocessed BOLD: structural intensity semantics plus time-volume navigation.

## 4D behavior and metadata

For a 4D NIfTI, the viewer exposes volume index, play/pause, and playback speed. Windowing is calculated from the complete loaded series so playback does not visibly pump the window from frame to frame. Publication export rerenders the selected frame at the requested resolution.

The viewer metadata disclosure reports available header-derived dimensions, voxel sizes, datatype code, frame count, scaling slope/intercept, qform/sform codes, and the sampled finite intensity range. It intentionally describes the file and display state without making a registration or quality judgment.

## Current limitations

- Official fMRIPrep reportlets remain the authoritative registration, distortion-correction, and confound QC views.
- The interactive viewer does not implement cross-space resampling, checkerboard registration comparison, motion plots, confound-correlation plots, carpet plots, or surface/GIFTI/CIFTI rendering.
- Transform files are listed and downloadable but not visualized as images.
- Report behavior depends on referenced reportlet assets remaining present in the original fMRIPrep output tree. Missing assets are surfaced as missing requests; Neuravian does not fabricate replacements.
